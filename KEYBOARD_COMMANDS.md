# Keyboard Commands (implemented — src/ui/keys.ts is the source of truth)

From design doc §23.2, amended for the host-as-player model. All commands
are mode-aware: none may fire inside text fields (except Escape, which
always works), and only commands legal for the current game state
execute. Every command also has a clickable on-screen control
(dual-modality requirement). The table below is generated by hand from
`KEY_BINDINGS` in `src/ui/keys.ts` — that array is the single source of
truth (it also drives the help menu's rows and the keyboard explorer's
descriptions); update this file whenever a binding there changes.

| Key | Function | Legal states |
|---|---|---|
| R | Repeat current game prompt | every play state |
| S | Speak current game and team status | every play state |
| A | Speak available actions and usable resources | every play state |
| T | Speak all team positions | every play state |
| ? | Open help menu (list of shortcuts legal right now, Up/Down to browse); a 2nd ? while help is open closes it and enters keyboard explorer (keys describe themselves, nothing executes; Escape exits) | every play state |
| H or F1 | Open/close the help menu (plain aliases; no explorer chaining) | every play state |
| Enter | Confirm or advance | every play state |
| Escape | Back or cancel when safe; opens the game menu when there's nothing to cancel | every play state (and text fields) |
| Space | Pause or resume the current produced audio clip | every play state |
| L | Listen again: replay the current task audio (respects its play cap) | resourceWindow, awaitingAnswer |
| X | Stop the current produced audio clip | every play state |
| N | Skip optional narration (never task audio) | every play state |
| Ctrl+Z | Undo the most recent reversible action (press-twice confirm) | every play state (gated further by canUndo()) |
| C | Rule the current answer correct | answerReveal, communityEvent |
| I | Rule the current answer incorrect | answerReveal, communityEvent |
| K | Rule the current answer skipped | answerReveal only (no "skipped" option on a relay answer) |

"Every play state" means the 12 states the Phase 2 engine actually
reaches: ready, beginTurn, forkChoice, resourceWindow, awaitingAnswer,
answerReveal, recoverDecision, teachingReveal, surplusDecision,
landmarkIntroduction, communityEvent, gameSummary. (`taskPreview`,
`taskPresentation`, `progressResolution`, `stageCompletion`, and
`hostRuling` exist in the `GameState` type but are never entered by the
current engine — see OPEN_QUESTIONS.md.)

Notes:

- The host never receives the answer before the reveal (host-as-player
  model); the reveal command shows the official answer and accepted
  alternatives to the whole room at once.
- Ruling keys (C/I/K) are single-press, not press-to-confirm — undo is
  one gesture away if the host misjudges. Press-twice confirm is reserved
  for Ctrl+Z and ending a session early from the game menu.
- The input firewall keeps every game key except Escape out of setup text
  entry (team-name fields).
- The setup wizard's own cursor lists (journey/duration/pace/etc.) use
  arrow keys, Enter, Escape, and first-letter type-ahead locally; those
  are screen-specific selection UI, not part of this global table.
- The audio keys (Space/L/X/N) work only while playing. The Sound check
  screen (Welcome → Sound check) uses ordinary Tab + Enter on its buttons,
  including the same Pause/Stop/Skip transport buttons.
- Phase 7 added no new keys, only new on-screen controls reachable by Tab
  (no dedicated shortcut, matching C/I's precedent that only the most
  common actions get a letter): a contribution pledge now offers one
  "contribute N {resource}" row per unit from 1 up to the lesser of what
  the team owns and the configured cap, plus decline; a team holding a
  pending "choose a resource" grant gets a "share with Team X" row per
  other team alongside its own take-the-resource rows (absent once that
  grant is itself a received gift — gifts can't be re-shared).
- Phase 8 added no new keys either: Welcome's "Resume game" (shown above
  "New game" when a save exists) and the game menu's "Game log…" and
  "Delete saved game" are ordinary Tab-reachable buttons, same precedent
  as Phase 7's above.
- This file is the living record; update it whenever `KEY_BINDINGS`
  changes in `src/ui/keys.ts`.
